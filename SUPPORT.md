# Support

Welcome to the IN2NEXT Nexus support guide.

## Before Asking for Help

Before opening a support request:

1. Read the README.
2. Search existing issues.
3. Search existing discussions.
4. Review the documentation.
5. Check the roadmap if your question concerns future functionality.

## Where to Get Help

Use the appropriate GitHub channel:

| Need | Recommended Channel |
|---|---|
| General question | GitHub Discussions |
| Bug report | GitHub Issues |
| Feature proposal | GitHub Discussions / Issues |
| Documentation issue | GitHub Issues |
| Security vulnerability | Private security reporting |
| Contribution question | GitHub Discussions |
| Community conduct issue | Private maintainer contact |

## Bug Reports

A useful bug report should include:

- What happened.
- What you expected.
- Steps to reproduce.
- Relevant environment information.
- Logs or error messages where safe.
- Version or commit.
- Minimal reproduction where possible.

Do not include passwords, API keys, tokens, or other secrets.

## Feature Requests

Feature requests should explain:

- The problem.
- Who experiences the problem.
- Proposed solution.
- Alternatives considered.
- Potential impact.
- Security or privacy considerations.

## Security Issues

Do not report security vulnerabilities publicly.

Follow [`SECURITY.md`](SECURITY.md).

## Documentation Issues

Documentation improvements are welcome.

Examples:

- Incorrect instructions
- Missing examples
- Broken links
- Unclear explanations
- Missing setup information
- Outdated architecture information

## Community Discussions

Discussions may be useful for:

- Ideas
- Questions
- Architecture conversations
- Research
- Community proposals
- Collaboration

Please keep discussions constructive and relevant.

## Response Expectations

Nexus is an open-source project.

Response times may vary depending on:

- Issue complexity
- Maintainer availability
- Security impact
- Community participation
- Project maturity

A lack of an immediate response does not necessarily mean that an issue has been ignored.

## Responsible Support

Support requests should not include:

- Passwords
- Private keys
- API credentials
- Personal data that is not necessary
- Confidential business information
